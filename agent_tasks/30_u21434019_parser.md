# u21434019 - parser and syntax diagnostics

## Objective

Consume tokens predictively, accept exactly the supplied SPL grammar and build
the original-grammar concrete syntax tree.

## Owned paths

```text
src/spl_frontend/parser.py
tests/unit/test_parser.py
tests/fixtures/parser/
```

The parser may import token, diagnostic and tree contracts. It must not read
source characters, write XML or implement the CLI.

## Implementation checklist

- Use one clearly named parsing method per grammar non-terminal.
- Implement every production in `02_spl_reference.md`.
- Implement all nullable productions with correct prediction/follow logic.
- Handle assignment versus call from the token after the name.
- Handle variable term versus call from the token after the name.
- Do not use uncontrolled backtracking or parse-and-rewind.
- Build `SPL_PROG` as the root and original non-terminals as inner nodes.
- Add a leaf for every consumed source token in input order.
- Do not create a leaf for internal EOF or literal `$`.
- Do not leak left-factoring helper names into the output tree.
- Require EOF after the complete program and reject trailing input.
- Centralise `peek`, `match`, `expect` and error creation.
- Include unexpected token, expected token/set, position and a useful hint in
  syntax errors.
- Keep parser state per parse; no global cursor or tree.

## Required grammar coverage

- Smallest valid program and nullable declarations/algorithm.
- Variable declarations and chains of function declarations.
- Void and numeric functions, parameters, nested `P` and return forms.
- Every instruction alternative.
- String and term output.
- Calls with empty, one and multiple inputs.
- Assignments and plain name/number terms.
- Every arithmetic operator and negation.
- Every boolean operator and comparison.
- Branches and both loop forms.
- Deep nesting and multiple sequential instructions.

## Required negative tests

- Wrong or missing colon, semicolon, brace or parenthesis.
- Missing return or branch keyword.
- Name followed by neither `=` nor `(` in instruction position.
- Invalid term/name lookahead.
- Missing operands and extra operands.
- Instruction in an invalid grammar position.
- Unexpected EOF at several nesting depths.
- Valid prefix followed by trailing tokens.

Tests must use manually constructed tokens first so parser work never waits for
the lexer. Add lexer-to-parser integration tests only after both are merged.

## Handoff to tree/XML owner

Provide representative trees for the smallest valid program, one function,
one branch and one loop. Confirm that only the builder API was used.

## Acceptance

- Every grammar production has at least one positive test.
- Every prediction decision has a focused test.
- Invalid input raises one reliable structured syntax error.
- Parser never inspects raw source or writes XML.
- Result validates through the shared tree validator.
