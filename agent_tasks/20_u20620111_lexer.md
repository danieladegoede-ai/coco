# u20620111 - source reader, tokens and lexer

## Objective

Turn plain ASCII `SPL.txt` into a complete, immutable token list with accurate
locations and clear lexical errors.

## Owned paths

```text
src/spl_frontend/source.py
src/spl_frontend/tokens.py
src/spl_frontend/lexer.py
src/spl_frontend/token_stream.py
tests/unit/test_source.py
tests/unit/test_lexer.py
tests/unit/test_token_stream.py
tests/fixtures/lexer/
```

Do not inspect grammar productions or create syntax-tree nodes.

## Implementation checklist

- Load input bytes and reject non-ASCII data with a positioned diagnostic.
- Define every token type from the official grammar.
- Preserve exact token lexemes without trailing separators.
- Implement `NUM` exactly, including signs, leading zeros and decimal-ending
  restrictions.
- Implement user-defined names beginning with `#` and lowercase/digit content.
- Implement strings and their restricted character set.
- Recognise every keyword and punctuation token.
- Enforce token termination consistently for all token categories.
- Centralise provisional SP/CR/LF/CRLF handling in one helper.
- Reject unsupported whitespace such as tab unless the tutor says otherwise.
- Track zero-based offset and one-based line/column through every supported
  newline form.
- Emit exactly one internal EOF token with empty lexeme.
- Reject a literal `$` rather than treating it as EOF.
- Make repeated calls deterministic and avoid global state.
- Implement the list-backed token stream contract.

## Minimum positive tests

- Each keyword and punctuation token.
- `0`, positive/negative integers and valid decimals.
- Short, long and boundary user names.
- Empty and non-empty valid strings.
- Multiple tokens across spaces and line endings.
- Empty input and whitespace-only input producing EOF.

## Minimum negative tests

- `-0`, leading-zero integer and decimal ending in zero.
- Missing token separator.
- Uppercase or unsupported name characters.
- Missing string quote, space in string and unsupported string character.
- Non-ASCII byte, tab and unknown symbol.
- Literal `$` in the source.
- Accurate error position after CR, LF and CRLF.

## Handoff to parser owner

Provide:

- the complete `TokenType` list;
- examples of manually creating tokens in tests;
- documented EOF behaviour; and
- a token dump of at least one representative valid program.

## Acceptance

- All lexical categories have positive and negative tests.
- No parser or tree dependency exists.
- Every error contains path, line, column, stable code and helpful message.
- Token output satisfies the approved shared contract.
