\heading{5. Input, output and errors}
With no argument the compiler reads \texttt{SPL.txt} in the \emph{current directory}. To use a different ASCII source file, pass one path, quoted when it contains spaces:
\begin{lstlisting}
.\group-2.exe "path\to\input with spaces.spl"
./group-2 "path/to/input with spaces.spl"
./macos/group-2 "path/to/input with spaces.spl"
\end{lstlisting}
Successful compilation is silent, returns exit status 0, and writes \texttt{tree.xml} and \texttt{program.cpp} in the current directory. The XML retains original token spellings and tree IDs. The C++ file is human-readable and includes a commented, inactive function code mine followed by one executable \texttt{main}. Run the C++ compilation command before expecting screen output from the SPL program.

\textbf{Input rules.} Every token, including the last, must end in a space or supported newline (LF, CR or CRLF). Tabs, non-ASCII input, a literal \texttt{\$}, uppercase user names, spaces inside strings, and unsupported tokens are rejected. Names begin with \texttt{\#}; numeric zero is \texttt{0}, not \texttt{-0}. Decimals must end in a nonzero fractional digit. Preserve the trailing newline when editing the example.

\begin{tabular}{@{}p{17mm}p{128mm}@{}}\toprule
Status & Meaning\\\midrule
0 & Complete compiler success; fresh XML and C++ outputs are available.\\
2 / 3 & Incorrect command usage / input or path-alias problem.\\
4 / 5 / 6 & Lexical / syntax / tree error.\\
7 / 8 & Name or scope error / type or whole-program numeric conflict.\\
9 & Code-generation or output-publication error.\\
70 & Unexpected internal failure or an OS error preventing output cleanup.\\\bottomrule
\end{tabular}\par\medskip
Diagnostics go to stderr and identify the input path and source location. Ordinary failed full compilations remove both old outputs so they cannot be mistaken for current results. Input/output alias rejection occurs before deletion and preserves the source. An OS error that prevents cleanup is reported explicitly.

\heading{7. Target compiler preference (Announcement 34)}
\textbf{Use \texttt{g++} with C++17.} The lecturer permits the C++ designation; \texttt{std::cout} requires C++ support. The generated file is intended for visual inspection before its run-test. The release pipeline checks the target corpus using both GNU C++ 13 and the GNU C 13 driver with explicit C++ language/link options:
\begin{lstlisting}
gcc -x c++ -std=c++17 program.cpp -lstdc++ -o program
\end{lstlisting}
On Windows use \texttt{-o program.exe}. Install a GNU toolchain that supplies both the C++ frontend and \texttt{libstdc++}. The compiler executable itself does not invoke or require \texttt{g++}; that tool is needed only for the generated program.

\heading{9. Implemented language decisions}
The compiler uses the following final language and output rules. They follow the supplied specifications, Announcement 34's target-language clarification and the tested release contract.
\begin{itemize}
\item Variables use nearest-current/ancestor scope; sibling and cousin declarations are invisible. Calls target only the current P's immediate function declarations. Duplicate declarations, own-parameter masking, overloads and recursion are rejected.
\item Functions are statically inlined. Actuals are evaluated left to right into fresh captures before copying to cloned formals. Numeric calls copy their return value into the caller continuation; void calls have no numeric result. Actual/formal counts must match. Boolean \texttt{and}/\texttt{or} short circuit; \texttt{not} reverses the branch destinations.
\item All numbers use one mode: \texttt{int} unless division or decimal NUM selects \texttt{float}. Any \texttt{mod} plus \texttt{div} is rejected with the specified conflict message; \texttt{mod} with any decimal NUM is rejected. Strings do not select numeric mode.
\item Native integers and single-precision floats are used, with normal \texttt{std::cout} output (six significant digits for floats). Arbitrary precision, overflow and division by zero are not promised. Programs used in acceptance initialize their values and terminate. Static inlining has an explicit 1,000,000-instruction resource guard.
\item Variable/function names use separate namespaces; returns resolve in the function body's scope. Symbol/type data are internal maps. The published assessment outputs are \texttt{tree.xml} and \texttt{program.cpp}.
\end{itemize}
